# AUDIT QUALITÉ — Windows 11 Toolbox v3.2.0 (QA-AUDIT-v3.2)

> **Date** : 2026-10-30 · **Type** : audit qualité/bugs (statique + tests de parsing PowerShell 5.1 réels, aucune exécution de l'application, aucune modification de code, aucun commit)
> **Périmètre** : `Windows-Toolbox.ps1` (3202 lignes, lu intégralement), `Installer-Toolbox.ps1`, `Uninstall-Toolbox.ps1`,
> `Setup-GUI-Toolbox.ps1`, `Updater-Toolbox.ps1`, `Build-Toolbox.ps1`, `Setup-Toolbox.cmd`, `Lancer-Toolbox.cmd`,
> `installer.iss`, `version.json`, `checksums.txt`, `mac/Mac-Toolbox.command`.
> **Note** : le working tree audité est en version **3.2.0** alors que `version.json` en ligne (branche `main`) propose **3.2.2** — l'audit porte sur la copie locale.
> Le faux positif Kaspersky PDM n'est pas traité (documenté en en-tête du script, lignes 17-24). Les constats à dominante sécurité
> (chaîne d'update, TOCTOU temp élevé, corbeille « sans risque », TPM, fail-open SHA256…) sont déjà couverts par `docs/SECURITY-AUDIT-v3.2.md` (F1-F13) et ne sont pas dupliqués ici.
>
> **Méthode** : chaque constat cite `fichier:ligne` vérifié. Les 3 erreurs de parsing ont été **reproduites réellement** avec
> `[System.Management.Automation.Language.Parser]` et `powershell.exe` 5.1.26100 (test de binding `-First 1Product`, test de chargement de `[Microsoft.VisualBasic.Interaction]`).

**Verdict** : architecture saine et compatible PS 5.1 (aucun P0, aucune régression de parsing sur le cœur), mais **4 fonctionnalités sont mortes au clic** et le build EXE — canal principal des clients — a 3 relances cassées. Le lot P1 est corrigeable en une passe courte ; recommander ensuite l'ajout d'un test de régression automatisé qui re-parse chaque `$script:Cmd*` et chaque here-string (le script d'extraction utilisé pour cet audit peut servir de base) avant chaque publication.
